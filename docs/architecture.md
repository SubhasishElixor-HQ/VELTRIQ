# Architecture and operating model

## End-to-end flow

```text
synthetic / authorized JSONL
        ↓ validate schema, timestamps, quality, size
FastAPI local import API ──────────────── local web UI (React/Vite)
        ↓ PostgreSQL transaction                     ↓ constrained question
PostgreSQL trips/signals/events/logs ←── query service (fixed intent + parameterized SQL)
        ↓ evidence records                         ↓ deterministic metric/summary
optional localhost model (summary only) → answer + evidence + caveats
```

### Components

- **UI:** React 19, TypeScript, Vite. One local service-engineering workbench; no user accounts or remote analytics in the demo.
- **API:** FastAPI/Pydantic. Versioned `/api/v1` routes, bounded request bodies, local CORS allowlist, loopback deployment.
- **Data:** PostgreSQL 16 with foreign keys and indexes. The app connects using `VEHICLEGPT_DATABASE_URL`; the included Compose service binds only to loopback and persists data in a named volume. JSONL is the human-auditable exchange format. The current MVP retrieves logs by trip/time window.
- **Analysis:** Five fixed query intents. Application code selects event windows, computes basic aggregates, returns supporting rows, and labels limitations. SQL is never generated by the model.
- **Optional explanation:** OpenAI-compatible chat completions on localhost only. The model receives question plus bounded evidence and can provide concise wording. A failed call falls back to a deterministic summary. It is not required to use the system.
- **Demo data:** Deterministic Python generator. `SIM-` trip IDs flag synthetic evidence in responses and the UI.

## Trust boundaries and behavior

1. A user chooses a JSONL file. The importer caps bytes and records, validates each record and timezone-aware timestamp, inserts transactionally with foreign keys, and ignores duplicate primary keys. Errors are summarized; malformed records do not become model instructions.
2. Query detection selects a supported fixed intent and event type. API parameters are bounded, and database access uses parameter binding.
3. The query service retrieves a bounded evidence set. Numeric comparisons and time windows are computed in Python/SQL, not inferred by a generative model.
4. The user sees answer, source, time, trip, signal quality, and limitations. A missing row means “not present in this dataset,” not “did not happen.”

## Intentional non-goals

No vehicle network connection, CAN bus reader, actuation, cloud inference, automated repair recommendation, root-cause certification, fleet telemetry collection, OEM data connector, multi-tenancy, or production identity system. These require separate customer discovery, security and safety analysis, and commercial agreements.

## Production evolution (only after pilot evidence)

For a small controlled pilot, add an adapter for one customer-approved export, mapping/units registry, user identity, tenant-scoped authorization, immutable audit trail, encryption and retention controls, migration tooling, backups, operational monitoring, a packaging/update mechanism, and an agreed local inference runtime. Keep model output subordinate to the evidence service. If scaling beyond a single local workstation, re-evaluate the threat model and storage architecture rather than exposing this demo server.
